# CHAT-772-001

Decode `SV_CMD_TALK` so an ordinary session may use chat without producing an
unsupported opcode, residual bytes, or a parser desynchronisation.

This was the sole remaining qualification on `UNREAL-SLICE-001` criterion 12.

Packet structure, the source trail it was derived from, and the ownership
decision are in `docs/protocol772/TALK.md`. This file records what was run.

## Result

`PASS`.

## Source truth

Derived entirely from the Fusion32 source in `reference/`, not from modern
Tibia documentation and not from another server.

| What | Where |
| --- | --- |
| `SV_CMD_TALK = 170` | `reference/game/src/connections.hh:120` |
| Three `SendTalk` overloads | `reference/game/src/sending.cc:1328`, `:1365`, `:1402` |
| `SendString` = word length + bytes | `reference/game/src/sending.cc:149` |
| `TALK_MODE` | `reference/game/src/enums.hh:651` |
| Modes 18..23 belong elsewhere | `reference/game/src/sending.cc:1618`, `SendMessage` |

All three overloads emit opcode 170 and share a head of
`quad StatementID`, `string Sender`, `byte Mode`. The mode then decides the
tail, because the server selects an overload by argument types at the call site
and the client can only recover that choice from the mode.

Two details would each have desynchronised a decoder written from assumption:

- `TALK_ANONYMOUS_CHANNELCALL` sends an **empty** sender rather than omitting
  the field. Treating anonymity as an absent field loses two bytes.
- `TALK_GAMEMASTER_REQUEST` is the one mode that inserts a quad between the
  mode and the text.

## Supported forms

| Layout | Modes | Tail after the shared head |
| --- | --- | --- |
| Positional | `SAY` 1, `WHISPER` 2, `YELL` 3, `ANIMAL_LOW` 16, `ANIMAL_LOUD` 17 | `word x`, `word y`, `byte z`, `string Text` |
| Channel | `CHANNEL_CALL` 5, `GAMEMASTER_CHANNELCALL` 10, `HIGHLIGHT_CHANNELCALL` 12, `ANONYMOUS_CHANNELCALL` 14 | `word Channel`, `string Text` |
| Plain | `PRIVATE_MESSAGE` 4, `GAMEMASTER_REQUEST` 6, `GAMEMASTER_ANSWER` 7, `PLAYER_ANSWER` 8, `GAMEMASTER_BROADCAST` 9, `GAMEMASTER_MESSAGE` 11 | `quad Data` for `GAMEMASTER_REQUEST` only, then `string Text` |

`ANONYMOUS_BROADCAST` 13 and `ANONYMOUS_MESSAGE` 15 are declared in `enums.hh`
and accepted by no overload, so they cannot arrive under this opcode. An
unrecognised mode is refused with `UnknownTalkMode`, consuming nothing, rather
than being given a tail it never had.

## Semantic contract

`ServerUpdateKind::Talk` carrying a `TalkUpdate`: `statement_id`, `speaker`,
`mode` with `TalkModeName`, `layout`, `text`, and three flagged optionals —
`has_position`/`position`, `has_channel`/`channel`,
`has_request_data`/`request_data`. Flags rather than sentinels, so absent
cannot be confused with zero.

Talk stores nothing in `WorldState`. Fusion32 keeps no per-connection chat
history, so a client-side transcript would be a feature this client does not
have, and holding one in `WorldState` would make it look like server state.
Reasoning in `docs/protocol772/TALK.md`.

## Two defects the tests caught

**A miscomputed golden.** The hand-written expectation encoded `y = 32218` as
`0xBA` where it is `0xDA`. The emitter was right and the golden was wrong,
which is precisely why this suite asserts goldens before letting structural
tests depend on the emitter.

**A stale assertion in `player_state_tests`.** It listed opcode 170 among the
commands that are *still unsupported*, which was true until this milestone and
became false the moment talk decoded. Removing it silently would have left
nothing checking the claim, so the list now has a matching positive assertion
that a well-formed talk decodes whole.

## Live validation

Real stack: `Tibia.exe` 7.72 (Player A, operator-driven) + Fusion32 + Unreal
running Protocol772Core (Player B).

Three talk commands decoded, in `chat_live_decoded_talk.log`:

```text
talk [Say]     at 32097,32205,7, Test Player A: "asdasdsa"
talk [Whisper] at 32097,32205,7, Test Player A: "asadasd"
talk [Whisper] at 32097,32205,7, Test Player A: "asdasd"
```

Mode resolved by name, speaker correct, position exact, text intact.

`TALK_YELL` was attempted and **refused by the server**: yelling is level-gated
in 7.72 and both characters are level 1. That is Fusion32 behaving correctly,
not a decoder limitation, and no yell packet was therefore produced to decode.
The channel and plain forms need a channel or a gamemaster, neither of which
this sanitized two-account runtime has; they are covered deterministically and
were not exercised live.

### The position field cross-checks itself

The decoded talk position is `32097,32205,7`. Independently, the same
snapshot's creature list places creature `1001` — Player A — at exactly
`32097,32205,7`, tracked through an entirely separate path (creature
descriptors and move commands, never the talk decoder).

Two unrelated decoders agreeing on the same field is stronger evidence that
the talk position is read correctly than any assertion inside the talk tests.

## UNREAL-SLICE-001 criterion 12

The qualification is **removed for the tested scope**.

Criterion 12 asked for zero unsupported opcodes, zero protocol anomalies and
zero residual bytes in a live window. It was qualified only because
`SV_CMD_TALK` stopped the frame walk whenever anyone spoke. A session that used
chat now reaches all three zeros, so the reason for the qualification no longer
exists.

Scope of the removal, stated plainly: positional talk is proven live; channel
and plain forms are proven deterministically but were not exercised against the
runtime, because this sanitized runtime has no channel and no gamemaster. An
unknown mode still stops the walk by design, and that is the correct behaviour
rather than a remaining gap.

This does not rewrite the earlier report. `UNREAL-SLICE-001.md` keeps its
record; this supersedes the qualification.

## Regression

No previous milestone's behaviour changed. The corrected movement accounting
introduced after `UNREAL-SLICE-001` is intact, including the self-walk versus
external-relocation distinction, which the live snapshot exercises directly.

## Not in scope

No chat UI, no chat window, no text above creatures. Talk is decoded, surfaced
and logged; nothing draws it. The Unreal module still contains no protocol
knowledge: the bridge resolves the mode to a name so nothing above it sees a
mode number.
